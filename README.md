# Interior Planner

[멀티플로어 인테리어 플래너 기획서](https://app.notion.com/p/3ddc883fa202819abe0fdb71a2bb952d)를 바탕으로 만든 React + TypeScript 에디터 시작 프로젝트입니다.

## 시작하기

Node.js 20.19 이상 또는 22.12 이상에서 실행합니다. 패키지 설치에는 npm 레지스트리 접속이 필요합니다.

```bash
npm install
npm run dev
```

브라우저에서 터미널에 표시된 로컬 주소를 엽니다. `npm run build`, `npm run lint`, `npm run test`로 확인할 수 있습니다.

## 현재 구현된 내용

- Vite, React, TypeScript, SCSS Module, Zustand, ESLint, Prettier, Vitest 설정
- 에디터 레이아웃과 1m 간격 Grid
- 휠 확대·축소: 마우스 위치를 기준으로 확대
- Space + 왼쪽 드래그, 이동 도구 + 왼쪽 드래그, 가운데 버튼 드래그로 Pan
- 화면 초기화, 좌표 표시, World ↔ Screen 변환 및 Polygon 면적 계산 유틸리티
- 임시 에디터 상태와 저장 대상 프로젝트 상태의 분리된 Store
- 공간 도구로 Vertex와 Wall을 그리고 시작점 근처를 클릭해 Room 생성
- 공간 그리기 중 1m 격자 교차점 근처에서 포인터 미리보기와 클릭 좌표 보정
- 직전 Vertex 기준 수평·수직 보정과 시작점 Snap 미리보기
- 그리는 중인 벽과 완성된 방의 벽 길이 표시, `Esc` 또는 직전 점 취소 버튼으로 마지막 클릭부터 되돌리기
- 완성된 방의 Shoelace 면적을 도면과 속성 패널에 표시하고 ㎡/평 단위 전환
- 프로젝트 목표 면적 입력과 공간 면적 합계의 부족·초과 표시
- 선택 도구에서 공간의 꼭짓점 드래그와 벽 길이 입력, 교차·겹침·짧은 벽 검사
- 선택 도구에서 방 내부를 드래그해 전체 이동. 이동 중 면적을 미리 보여 주고, 놓으면 저장 상태에 반영
- 분할 도구에서 기존 방의 벽 위 시작점, 필요한 내부 꺾임점, 다른 벽 위 끝점을 클릭해 나누기. 각 방의 면적과 공간 수를 갱신하고 전체 면적은 유지
- 도구 단축키: `V` 선택, `R` 공간 그리기, `F` 물품 배치, `D` 분할. 입력 필드에 포커스가 있을 때는 동작하지 않음
- 기본 책상·의자 Palette와 가구 배치 미리보기. `+ 물품 추가`에서 이름·종류·기본 크기·모양·색상을 정해 사용자 물품을 등록할 수 있음. Palette 선택 또는 `F`로 배치 모드에 들어가 도면을 클릭하면 현재 층에 추가
- 가구 배치 시 기존 가구의 중심을 따라 가로·세로 정렬 보정. 같은 줄의 가구 두 개 옆에서는 가구 외곽 사이의 빈 간격을 맞춰 세 번째 가구를 배치
- 물품마다 기본 크기·색상·모양을 제공하고, 배치 전 설정이나 배치 후 속성 패널에서 가로·세로 크기, 색상, 사각형·원·삼각형 모양 변경
- 선택한 물품을 드래그해 이동하고, 선택 테두리 오른쪽 아래 손잡이로 크기 변경, 위쪽 손잡이나 속성 패널의 각도 입력으로 회전. 속성 패널의 버튼 또는 `Delete`/`Backspace`로 삭제
- 물품 드래그 이동은 화면 픽셀 차이를 확대 배율(px/m)로 나눈 미터 좌표로 기록. 이동 중 미리보기 후 손을 놓으면 프로젝트 상태에 반영
- 선택한 물품의 X·Y 좌표와 가로·세로 크기를 Inspector에서 미터 단위로 직접 입력. 좌표는 도면 원점 기준이며 회전 전 왼쪽 위 지점을 뜻함
- 물품 도구는 선택 항목 없이 시작. Palette에서 물품을 고른 뒤 도면이나 Palette에서 우클릭하면 도구를 유지한 채 물품 선택을 해제
- 선택 도구에서 `Shift+클릭`으로 물품 다중 선택. 빈 도면을 드래그하거나 방 위에서 `Shift+드래그`하면 닿는 물품을 영역 선택하며, `Shift+드래그`는 기존 선택에 추가
- 선택된 물품 하나를 드래그하면 선택 집합 전체가 간격을 유지하며 이동. 이동 중 1m 격자와 선택되지 않은 물품의 중심에 가로·세로로 맞추고 기준선을 표시
- 선택 도구에서 물품을 `Ctrl/Cmd+C`로 복사하고 `Ctrl/Cmd+V`로 붙여넣기. 여러 물품의 상대 위치와 외형을 유지하며 붙일 때마다 0.25m씩 대각선으로 옮겨 배치. 속성 패널 버튼으로도 실행 가능
- 선택 도구의 `Delete`/`Backspace`는 선택한 물품 중 잠기지 않은 항목을 삭제하고, `Esc`는 선택을 해제. 배치 모드의 `Esc`는 Palette 선택을 해제하며 공간·분할 도구의 `Esc`/`Backspace`는 직전 점 하나를 취소. 드래그 중 `Esc`는 해당 드래그만 취소
- 물품 잠금·해제는 속성 패널에서 설정. 잠긴 물품은 선택·복사할 수 있지만 이동·크기·회전·속성 변경·삭제는 할 수 없음. 복사한 물품을 붙여넣으면 새 물품은 잠금 해제 상태
- 도면의 생성·분할·이동·변형·삭제·잠금·면적 변경은 편집을 확정할 때 한 Command로 기록. 상단 버튼 또는 `Ctrl/Cmd+Z`로 되돌리고 `Ctrl/Cmd+Shift+Z`/`Ctrl+Y`로 다시 실행. 입력 필드에 포커스가 있으면 브라우저의 입력 취소를 유지
- Undo 직후 새 편집을 확정하면 이전 Redo 기록을 지움. 변화가 없는 입력은 Redo 기록에 영향을 주지 않음. Space 이동은 버튼·링크에 키보드 포커스가 있을 때 해당 요소의 기본 동작을 유지
- 도면 위 층 탭의 `+ 층 추가·관리`에서 층을 추가·전환·이름 변경·삭제. 새 층에는 현재 층의 공간을 복제하고, `일반 물품도 함께 복제`를 켜면 일반 물품까지 복제. 층별 도면을 나란히 표시하며 선택한 층의 도면은 중앙에 맞춰 편집하고 다른 층은 미리보기로 확인. 각 도면의 숨기기·크게 보기와 상단 층 탭으로 표시 범위를 조절할 수 있음. 숨기기는 데이터를 삭제하지 않으며 탭을 눌러 다시 표시. 층 삭제는 해당 층의 항목까지 함께 되돌릴 수 있음. 목표 면적 차이는 전체 층 면적을 기준으로 계산
- 상단 `반투명 겹쳐 보기`를 켜고 비교할 층을 선택하면 활성 도면에 해당 층의 공간 윤곽과 물품을 옅게 표시. 동일한 World 좌표로 겹쳐 보며 비교 층은 편집되지 않음
- Palette에서 물품을 검색해 선택하거나 직접 추가할 때 `층 연결 물품`을 켜면 계단·엘리베이터처럼 모든 층의 같은 좌표에 배치. 새 층에도 자동으로 표시되며 이동·크기·회전·잠금·삭제가 모든 층에 함께 반영됨. 각 층의 물품 위에 연결된 아래층·위층 이름을 표시
- 물품 목록 아래에서 층 연결 여부와 `한 개씩`/`여러 개 배열` 배치 방식을 선택. 배열 배치에서는 가로·세로 개수와 물품 사이의 간격을 입력해 클릭 지점을 중심으로 최대 100개를 놓음. 단일·배열 배치 모두 기존 물품과 가로·세로 정렬 및 같은 간격 보정을 지원. 배치 전체를 하나의 Undo/Redo 명령으로 기록하며 층 연결 물품도 층마다 같은 배열로 놓임
- 단축키 목록은 도면 상단 되돌리기 옆 `?` 버튼에 마우스를 올리거나 키보드로 초점을 맞추면 확인 가능
- 물품을 놓을 때 미리보기와 클릭 좌표가 공간 벽·모서리 근처에서 물품 외곽 기준으로 보정됨. 공간에는 회전 손잡이와 ±90° 버튼을 제공하고, 공간·물품 회전이 직각에서 8° 이내면 정확한 90° 단위로 맞춤

방을 나누려면 **분할** 도구를 선택하고 첫 번째 경계점, 필요한 내부 꺾임점, 반대쪽 경계점을 차례로 클릭합니다. 꺾임점 없이 끝내면 직선으로 분할됩니다. 벽 위의 격자 교차점과 꼭짓점에 맞춰집니다. 예를 들어 3×2m 방의 오른쪽 위를 ㄱ자로 나누면 1㎡와 5㎡가 됩니다. `Esc` 또는 `Backspace`를 누를 때마다 직전 꺾임점이나 시작점을 한 개씩 되돌립니다.

**진행 상태:** 2D·3D 편집 기능에 Firebase Auth와 Firestore 프로젝트 생성·목록·저장·불러오기를 연결했습니다. 자동 저장과 소유자별 접근 규칙은 로컬 에뮬레이터에서 검증했고, 규칙은 실제 Firebase 프로젝트에도 게시했습니다. 앱은 [Firebase Hosting](https://interior-planner-24d70.web.app)에 배포했습니다. 실제 계정으로 로그인·재접속해 도면이 복원되는지는 별도 확인이 필요합니다.

## Firebase 연결

1. `.env.example`을 `.env.local`로 복사하고 Firebase 콘솔의 웹 앱 **Config** 값을 채웁니다. `.env.local`은 Git에서 제외됩니다. 값을 바꾼 뒤 개발 서버를 다시 시작합니다.
2. Firebase Authentication에서 Google 또는 이메일/비밀번호 로그인을 활성화하고, 개발용 `localhost`를 승인된 도메인에 추가합니다.
3. Cloud Firestore의 보안 규칙은 현재 프로젝트에 게시되어 있습니다. 변경할 때는 `firebase deploy --only firestore:rules --project interior-planner-24d70`을 실행합니다. 이 규칙은 `/users/{uid}/projects/{projectId}`와 그 데이터 문서를 해당 로그인 사용자만 읽고 쓰도록 제한합니다.
4. 로그인한 뒤 **새 프로젝트 만들기**에서 이름을 입력합니다. 확정된 편집은 0.8초 뒤 자동 저장됩니다. 상단에 `자동 저장 대기 중`·`저장 중`·`저장됨`·`저장 실패` 상태가 표시되고, 실패하면 자동 재시도하거나 **다시 시도**를 누를 수 있습니다. 프로젝트 목록으로 이동하거나 로그아웃할 때도 최신 편집의 저장이 완료될 때까지 기다립니다.

저장 실패가 계속되면 화면을 닫기 전에 오류를 해결하고 **다시 시도**하세요. 저장되지 않은 변경이 있을 때는 페이지 이탈 경고가 표시됩니다. 저장되는 데이터는 프로젝트·층·공간·물품·팔레트·세트입니다. 선택, 화면 위치, 드래그 미리보기, Undo/Redo 기록은 저장하지 않습니다.

로컬에서 규칙과 재로그인 복원을 다시 확인하려면 Firebase CLI와 Java를 설치한 뒤 다음 명령을 실행합니다. 테스트는 `demo-interior-planner` 에뮬레이터에만 접근합니다.

```powershell
firebase emulators:exec --only auth,firestore --project demo-interior-planner "npm test -- src/services/firebase.integration.test.ts"
```

## Firebase Hosting 배포

`firebase.json`은 기본 사이트 `interior-planner-24d70`과 추가 사이트 `interior-plan`에 Vite의 `dist`를 게시하고 모든 앱 경로를 `index.html`로 연결합니다. 배포 전에 `.env.local`에 해당 Firebase 프로젝트의 웹 앱 설정값이 있어야 합니다. Hosting 배포 명령은 프로덕션 빌드를 먼저 실행합니다.

```powershell
firebase deploy --only hosting --project interior-planner-24d70
```

추가 사이트만 배포할 때는 `firebase deploy --only hosting:interior-plan --project interior-planner-24d70`을 실행합니다. Firebase Authentication 승인 도메인에 `interior-plan.web.app`이 등록되어 있습니다.

공개 주소: https://interior-planner-24d70.web.app · https://interior-plan.web.app

## 데이터 및 좌표 규약

- World 좌표, 위치, 길이는 **미터**, 면적은 **㎡**로 저장합니다. 평은 표시할 때만 변환합니다.
- Viewport의 `x`, `y`는 화면 좌상단을 기준으로 한 도면 원점의 CSS 픽셀 위치이고 `scale`은 픽셀/미터입니다.
- `editorStore`는 선택, 도구, Viewport처럼 저장하지 않는 상태를 소유합니다.
- `projectStore`는 향후 Firestore에 저장할 정규화된 프로젝트/층/공간/오브젝트 데이터를 소유합니다.
- 드래그 중 임시 변경은 Editor Store에 두고, 확정한 프로젝트 변경만 Command 기록에 추가합니다. Undo/Redo 기록은 최근 100개까지 실행 중 상태에 보관합니다.
