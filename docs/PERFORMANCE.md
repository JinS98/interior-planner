# 도면 렌더링 측정

2026-10-15, Windows의 Headless Chrome 155와 Vite 개발 서버에서 같은 EditorCanvas를 측정했습니다. 한 개의 60 × 25m Room에 0.8 × 0.6m 책상 100·500·1,000개를 50열로 배치했습니다. 캔버스는 1200 × 800 CSS px, 브라우저 창은 800 × 600 px, 배율은 20px/m입니다. 창 밖의 물품도 SVG DOM에는 모두 생성됩니다.

각 개수에서 첫 실행으로 모듈을 준비한 뒤 새 페이지 3회를 측정했습니다. 최초 표시는 React Profiler의 첫 커밋 시간, 화면 이동은 Viewport X를 20px 바꾸는 동작, 커서 이동은 Pointer Event를 보내는 동작입니다. 화면·커서 이동은 각 페이지에서 5회 실행하고 중앙값을 구했습니다. 표는 세 페이지 중앙값입니다. 단위는 ms이며 낮을수록 빠릅니다.

| 물품 수 | 최초 표시 전 | 최초 표시 후 | 화면 이동 전 | 화면 이동 후 | 커서 이동 전 | 커서 이동 후 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 17.8 | 17.1 | 6.3 | 0.9 | 5.8 | 0.9 |
| 500 | 61.9 | 49.1 | 7.3 | 0.8 | 6.4 | 0.8 |
| 1,000 | 95.0 | 89.5 | 10.4 | 0.9 | 15.2 | 0.9 |

1,000개에서 화면 이동 커밋은 약 91%, 커서 이동 커밋은 약 94% 줄었습니다. 최초 표시 시간은 실행마다 편차가 커서 개선을 단정하지 않습니다. 이 값은 개발 빌드의 React 렌더 시간으로, 전체 프레임 시간이나 실사용 기기의 FPS를 뜻하지 않습니다. 브라우저 창보다 큰 캔버스의 일부가 가려진 조건이므로 모든 물품을 한 화면에 표시하는 경우는 별도 측정이 필요합니다.

커서 이동마다 물품 배열을 다시 만들고 모든 `LayoutObjectShape`를 비교·렌더링하던 경로를 바꿨습니다. 물품 목록과 미리보기 배열을 메모이제이션하고, 물품 SVG 레이어를 `memo` 컴포넌트로 분리했습니다. 화면 이동은 레이어의 `translate`만 바꾸고 물품 내부 좌표를 다시 계산하지 않습니다. 배율이 바뀌거나 물품을 편집할 때는 해당 값에 맞춰 다시 렌더링합니다. 층 겹쳐 보기의 연결 물품 중복 제거도 `Set` 조회로 바꿔 물품 수의 곱에 비례하던 검색을 피했습니다.

재측정 방법:

```powershell
npm run dev -- --host 127.0.0.1
node benchmarks/run-render.mjs --rounds=3 --output=benchmarks/render-current.json
```

Chrome 설치 위치가 다르면 `BENCH_BROWSER` 환경 변수로 실행 파일 경로를 지정합니다. 원본 측정값은 [변경 전](../benchmarks/render-baseline.json)과 [변경 후](../benchmarks/render-optimized.json)에 있습니다.
